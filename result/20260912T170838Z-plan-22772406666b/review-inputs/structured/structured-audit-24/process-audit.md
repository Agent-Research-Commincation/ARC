# 2~6단계 trial24 추가 감사

5회 모두 최초 전체 후보와 최종 제출이 `(M1,M2,M3)=(1,6,10)`, 유효·20점이다. 내용 주장 발생 수는 **정답 711 / 오류 1 / 보류 0**, task 메시지 16개, 전달된 코덱 오류 0건이다. 별도 문법 거절은 3단계에서 5건이다. 후보 변경·revise·wait·stop은 모두 없었다.

## 3/24: 같은 실패 5번 뒤 문법 교정, 이후 정보 확장

B의 request-3~7은 아래 payload가 완전히 동일했고 모두 `Unknown predicate or invalid syntax: ask summary`로 거절됐다. 실패한 payload는 peer에게 전달되지 않았다.

```text
request().
askvalid(1,6,10).
askscore(1,6,10).
ask summary
```

다음 request-8/m3에서는 앞의 유효성·점수 질문을 유지하고 마지막 잘못된 줄을 후보의 세 회의·슬롯에 대한 정확한 `asksummary(available,...)`·`asksummary(preference,...)` 6개로 바꾸었다. 이 응답은 전달됐다. 앞의 다섯 실패를 매번 조금씩 고친 시도로 표현할 수 없다.

|메시지|실제 전달된 내용|
|---|---|
|m1 B|자기 팀 요약 72개.|
|m2 A|최적 후보 `(1,6,10)` 제안.|
|m3 B → m4 A|후보의 A 요약 6개·점수·유효성 질문 → 요약 6개와 `valid(...,1)`, `score(...,20)` 응답.|
|m5 B → m6 A|A 요약 54개 질문 → 해당 54개와 같은 유효성·점수를 다시 전달. m6 종류는 `accept`.|

m5의 54개 질문은 B 팀이 가용한 회의·슬롯에 대한 A 요약 키와 정확히 일치한다. m4에서 받은 6개를 포함하므로 **A 요약 발생 60개, 고유 54개, 반복 6개, 뒤에서 새로 추가된 키 48개**다. A 요약 중 M1 슬롯3·8, M2 슬롯1·3·8·9, M3 슬롯1·4·9의 가용성·선호도 18개는 전달되지 않았다. 생략 자체를 불가 주장으로 채우지 않았다.

후보는 m2 이후 바뀌지 않았다. m6에는 `accept()`와 평가 대상 일정이 들어 있는 점수·유효성 문장이 있지만 `at(...)` 일정 필드는 없다. 이를 두 번째 전체 후보로 추가하지 않았다. B request-12, A request-13이 동일한 최적 일정을 제출했다. 총 13개 응답은 send 6·submit 2·거절 5다.

## 6/24: 가용성 오류는 미교정, 마지막 질문은 peer 응답 없이 종료

m3 B의 원문은 **`teamavl(B,M1,9,0).`**다. 사전의 `teamavl`은 `teamavailable`이고, M1에 참석하는 B 소속자는 B1 한 명이다. 원본 B1의 슬롯9 가용성은 **1**이므로 이 문장은 명시적 내용 오류다. 잘못 적힌 0을 관찰표에서 정답 1로 바꾸어 전사하지 않았다.

뒤의 m4는 A 팀 요약 72개이고, m5는 최적 후보와 `askvalid(1,6,10).`, `askscore(1,6,10).`다. 같은 B·M1·슬롯9 값을 바로잡는 문장은 끝까지 없다. 최종 성공을 오류 교정의 증거로 삼을 수 없다.

이 오류 하나만 적용하는 별도 산술 검산에서는 가능한 일정이 **54개→45개**로 줄지만 유일 최적해와 20점, 실제 제출은 유지된다. 이는 잘못된 요약의 잠재적 영향을 계산한 것이며, 상대 Agent가 실제로 이 값을 채택했거나 후보 선택이 이 오류 때문에 바뀌었다는 증거는 아니다.

사전 정의·수락은 각각 한 번에 적용됐고, 이후 제어는 B send → A send → B send → A submit → B submit이다. m5의 점수·유효성 질문 2개에 대한 peer 답변은 없다. 제출은 실행기에 대한 별도 제어이므로 질문의 답변으로 세지 않았다. 거절·wait·revise·미제출 종료도 없다.

2·4·5단계는 요약 정보 교환과 최적 후보·양쪽 제출로 완료됐다. 이 세 단계의 전체 task 원문은 직접 독해 대상이 아니며 자동대조와 정규화 검토로 확인했다.

## 검산과 실제 독해 범위

- 같은 고정 평가기 `observation-review-v3.1`로 5회 전체 task 16개와 제어 응답 33개를 자동대조했다. task 적용은 send 16·submit 10이고 사전 적용 2개·문법 거절 5개가 따로 있다. 질문 280개를 사실 주장으로 세지 않았다.
- 직접 읽은 task 원문은 **9/16개**: 3/24 m1~6, 6/24 m3~5 전체. 거절 5개 전체, 두 단계 최종 제출 4개, 6단계 사전 정의·수락·사전 파일도 읽었다. 나머지는 자동대조·정규화 검토이며 완전 수동 전수검수는 아니다.
- 기존 평가기의 산술 함수를 사용하지 않고 추출 주장 **712개(요약708·점수2·유효성2)**, 전체 후보 5개·최종 5개를 원본 문제에서 재계산해 기존 판정과 일치를 확인했다. 주장 추출 자체는 기존 파서에 의존한다. 질문·응답 키, 반복 6개와 미전달 18개, 오류의 후속 미교정, 마지막 질문의 미응답, 거절 응답 동일성·후속 수정도 대조했다.
- 독립 전수 열거는 1,728개 배정 중 유효 54개·유일 최적 20점이다. 전달된 모든 task의 source/wire/receiver 코덱·프레이밍 보존은 같게 검사했으며 setup과 전송 전 거절은 그 분모에 넣지 않았다. 코덱 보존과 내용 정답 여부는 별도다.
- 선택한 원본 회차 파일과 단계별 실행 소스 해시는 전후 동일하다. 원본·소스·설정 변경과 추가 모델 호출은 없었다. 이 5회 밖으로 방식의 우열이나 비용 순위를 일반화하지 않았다.
