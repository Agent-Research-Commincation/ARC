# 자연어 1회차 최종 주석 검산

종료된 stage-1 trial-01의 최종 검토 주석을 임시 사본에서 검산한 결과, **맞는 주장 171개 / 틀린 주장 1개**를 확인했다. 실험 모델 호출은 0회다.

## 산출물과 검토자

- [최종 검토 주석](trial-01.json)
- [검산 결과와 입력·평가기 해시](trial-01-verification.json)
- [보존한 초기 주석](../trial-01.json)
- [독립 원문 감사](../trial-01-independent-audit.md)

초기 원문 주석 작성자는 AI `Codex /root/stages_5_6`이다. 독립 원문 감사와 이번 수정 적용자는 AI `Codex /root/stages_3_4`이다. 이 두 역할을 최종 주석의 `annotation_provenance`에 구분해서 기록했다. 원문 감사는 기존 주석의 단순 재집계와 구분되며, 이번 검산 자체는 최종 주석을 평가기에 넣는 로컬 규칙 검산이다. 사람의 독립 검수가 완료됐다는 의미는 아니다.

## 반영한 수정

메시지 1의 `available at slots ...`는 나열된 슬롯의 가용성을 명시하지만, 전체 목록의 완전성까지 명확히 선언하지는 않는다. 다음 12개 미나열 슬롯의 불가 주장을 확정 채점용 `claims`에서 제외했다.

| 회의 | 제외한 `available=0` 슬롯 |
|---|---|
| M1 | 0, 2, 5, 6, 10 |
| M2 | 0, 5, 10 |
| M3 | 2, 3, 6, 7 |

직접 나열된 24개 긍정 가용성 항목과 명시된 36개 선호값은 유지했다. 남은 긍정 가용성 항목의 note도 완결 목록을 단정하지 않도록 수정했다. 메시지 2~4의 주장 값은 그대로다.

다음 정확한 원문 발췌를 메시지 1의 `unjudgeable`에 보존하고, `notes`에서 **목록의 완전성만 해석 보류**임을 설명했다.

> For M1, my attendees are available at slots 1, 3, 4, 7, 8, 9, and 11;
>
> For M2, my attendee is available at slots 1, 2, 3, 4, 6, 7, 8, 9, and 11;
>
> For M3, my attendees are available at slots 0, 1, 4, 5, 8, 9, 10, and 11;

나열된 슬롯이 가용하다는 주장을 보류한 것이 아니며, 미나열 자체를 내용 오류로 센 것도 아니다. 제외한 12개 항목과 근거는 `annotation_provenance.excluded_inferred_claims`에 기록해 변경 이유를 추적할 수 있다.

## 임시 사본 검산 결과

| 항목 | 결과 |
|---|---:|
| 검토된 작업 메시지 | 4/4 |
| 확정 채점한 주장 | 172 |
| 맞는 주장 | 171 |
| 틀린 주장 | 1 |
| 의미 규약 때문에 판정 보류된 typed claim | 0 |
| 별도 발췌·해석 보류 표현 | 6 |
| 코덱 보존 오류 | 0 |
| 팀 요약 주장 | 135 |

별도 발췌 6개는 같은 의미의 항목이 아니다. 세 개는 이번에 추가한 가용성 목록의 완전성 해석 보류이고, 기존 세 개는 A팀 합계 10이라는 계산, 최적성 확인 요청, 조건부 최대값 계산이다. 따라서 이를 ‘틀린 주장 6개’ 또는 ‘사실을 판정할 수 없는 주장 6개’로 해석하면 안 된다. `complete`는 네 메시지의 검토 완료를 의미하며 모든 표현의 모호성 해소를 의미하지 않는다.

남은 내용 오류는 메시지 4의 **M3 슬롯 8 선호합계**다. 원문과 최종 주석은 발화값 `3`을 보존하며 평가기의 기대값은 `5`다. 정답에 맞춰 발화를 수정하지 않았다. 해당 오류의 영향은 평가기에서 `not_evaluated`로 남고, 최종 과제 성공 여부와 분리된다.

검산은 다음 순서로 수행했다.

1. 해당 원본 회차의 전체 파일을 `/private/tmp` 아래 새 임시 디렉터리에 복사했다.
2. 임시 위치에 수정 후보 JSON을 작성했다.
3. 실제 실행에 사용된 stage-1 worktree의 `experiment.records.write_trial_records`를 사용해 임시 원본 사본에서 별도 임시 출력 디렉터리로 검산했다. 주석과 이벤트 해시 및 모든 인용문 위치 검증도 통과했다.
4. `171 correct / 1 incorrect`, 주장 172개, 발췌 6개, 검토 4/4개, 코덱 보존 오류 0개를 assertion으로 확인했다.
5. 확인을 통과한 후보만 `reviewed/trial-01.json`에 저장했다. 원본 회차·초기 주석·초기 메모·독립 감사·지표 기준·실행 소스·설정 해시가 그대로인지 검증했다. 임시 검산 사본과 출력은 종료 시 정리했다.

검산의 사후 평가 정책 버전과 사용한 평가기·입력 해시는 `trial-01-verification.json`에 기록돼 있다. 검토본 주석 SHA-256은 `230c06d5535014096ac42cd60b7b6104b5cba531117e0dcbe305d9f1cc12f39d`이다.

이번 작업은 이 한 회차의 주석 수정과 로컬 검산에 한정된다. 실행 원본·실행 소스·설정은 수정하지 않았고, 다른 회차를 검수하거나 실제 실험을 추가 호출하지 않았다.
