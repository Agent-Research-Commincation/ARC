| 프로젝트의 실험 worktree | 없음. 여러 단계 실행을 요청할 때 새로 생성 |

## 구현한 동작

| 항목 | 현재 동작 |
|---|---|
| 자원 사용·대기 | 연구용 시간·토큰·메시지·행동·합의 횟수·본문 크기 상한 제거. 상태 확인 폴링은 종료 사유가 아님 |
| 행동 스키마 | 작업은 `send/revise/wait/submit/stop`, 6단계 준비만 사전 제안·수락·중단 |
| 제출·수정 | 동일한 유효 일정의 공동 제출이 성공. `send`는 제출 보존, 전달된 `revise`만 양쪽 무효화 |
| 질문·평가·재확인 | 특정 개인 사실·팀 요약·후보 유효성·점수 질문, 후보 평가 주장, 관측한 메시지 ID 재확인 |
| 4단계 전송 | 7,790개 의미 특성을 8,192개 float32 좌표에 저장. 메시지 ID는 별도 손실 없는 정수 영역에 저장하며 크기도 합산 |
| 종료 원인 | 과제 성공·실패, Agent 중단, 사용자 취소, 실제 오류, 최종 상태 미확정을 구분 |
| 원본·검수·내보내기 | 종료 원본의 파일 해시를 봉인. 검수는 새 버전, 내보내기는 지정한 검수만 사용하고 재채점하지 않음 |
| 배정·재개 | 같은 문제 5회, 선발화 A·B·A·B·A. 미실행 슬롯만 재개하고 이전 결과는 대체하지 않음 |
| worktree | 별도 Git 인덱스로 동일 소스 커밋을 고정. 사용자 HEAD·인덱스·수정 사항은 유지 |

## 실행과 기록

`python3 lab.py check`와 `python3 lab.py status`는 모델을 호출하지 않는다. `run N`, `run-many`, `observe`, `pilot`, `verify-live`, `resume`는 요청 범위에 따라 실제 모델을 호출할 수 있다. 이번 리팩터링에서는 호출하지 않았다.

`run-many`의 기본 동시 수는 1이다. 명시적 병렬 실행은 `--jobs`로 지정하고 실행 프로필에 기록한다. worker는 별도 실행 프로세스이며 Codex 서브에이전트 자체는 아니다. 별도 담당 서브에이전트는 요청받았을 때 진행·기록 관리를 맡길 수 있다.

원본 봉인은 변경 탐지를 위한 해시 검사다. 운영체제의 쓰기 권한을 제거하는 보안 장치는 아니다. 강제 종료로 확인되지 않은 회차는 성공·실패로 추정하거나 재실행하지 않는다. `resume`는 정상적으로 중단 기록을 남긴 계획을 대상으로 하며, 조정기까지 강제 종료돼 여전히 실행 중으로 남은 계획은 먼저 원본과 프로세스 상태를 확인해야 한다.

이전 문제는 `tests/fixtures/problem.json`으로 분리했고 새 문제는 `config/problem.json`에 있다. 선정·독립 검산 근거는 `config/problem-reference.json`, 구현 시작 전 소스 해시는 `docs/refactoring-baseline.json`이다. 이들은 실제 모델 실험 결과가 아니다.
