# Agent 간 소통 방식 비교 실험 계획

이 문서는 프로젝트의 연구 방향을 정리한다. [1차 실험 명세](phase-1-experiment.md)와 [실행 안내](../README.md)에 현재 설정과 검증 상태를 기록한다.

## 연구 목적

Agent들이 하나의 작업을 함께 해결할 때, 소통 방식에 따라 해결 과정과 효율이 어떻게 달라지는지 알아본다. 이후에는 사람이 활용할 수 있는 기록까지 평가 범위를 넓히고, 작업 유형에 따른 차이를 살펴본다.

## 비교할 소통 방식

다음 여섯 방식을 1~6단계로 고정한다. 사용자가 “N단계 해줘”라고 요청하면 해당 단계만 5회 실행한다. 단계는 소통 방식 번호이며 순서대로 실행할 필요는 없다. v1 모듈과 실행기를 구현했고 기본 협업을 같은 조건에서 매회 새 세션으로 5회 실행해 모두 최적해로 성공했다. 여섯 방식별 전송 검증과 단계별 본실험은 남아 있다. [요청 기반 실험 운영](experiment-operation.md)에 구현 정의와 한계를 기록한다.

1. **자연어**: 사람이 읽는 문장으로 의도, 정보, 결과를 교환한다.
2. **정해진 JSON 구조**: 공통 필드와 자료형에 맞춰 정보를 교환한다.
3. **논리식·관계 그래프**: 대상 간 관계와 조건, 규칙으로 정보를 표현한다.
4. **의미 벡터**: 정보를 벡터로 변환하고, 수신 측의 해석 장치를 통해 활용한다.
5. **기계어·바이트코드**: 실행 가능한 명령을 전달하고, 정해진 실행환경에서 해석한다.
6. **Agent 공동 언어**: Agent들이 합의하거나 학습한 기호와 조합 규칙을 사용한다.

비교 기준은 **기존 일반적인 Agent의 통상적인 소통 구성**으로 삼는다. 자연어 자체를 기준으로 가정하지 않는다. 통상적인 구성을 대표할 기준은 별도로 정의해야 한다. 현재는 소통 형식을 지정하지 않은 공통 실험 환경에서 동일 조건으로 5회 [기본 협업을 관찰](basic-observation-five-runs.md)했으며, 이를 곧바로 대표 기준으로 삼지는 않는다.

## 1차: 하나의 작업에서 소통 과정 관찰

- 서로 다른 팀의 일정 정보를 가진 두 Agent가 공동 시간표를 작성한다.
- 두 Agent는 Codex에서 GPT-5.6 Luna (`gpt-5.6-luna`), 추론 수준 `high`를 사용하며, 모든 비교 실행에서 이 설정을 고정한다.
- 전달할 내용과 질문·제안·수정의 순서는 Agent가 스스로 정한다.
- 각 소통 방식을 동일한 문제와 초기 정보로 5회씩 실행한다.
- 매 실행마다 두 Agent를 각각 새 세션으로 시작하고, 이전 실행의 대화와 결과를 전달하지 않는다.
- 소통 과정과 최종 결과를 기록한다.
- 반복 실행에서 나타난 차이를 정리하고 시각적으로 나타낸다.

첫 실험은 소통 방식별 특징과 후속 연구의 단서를 찾는 탐색 단계로 삼는다. 5회 결과만으로 보편적인 우열을 확정하지 않는다.

## 2차: 사람이 활용하는 기록까지 효율의 범위 확장

1차에서 얻은 인사이트를 바탕으로, Agent 간 반복 협업과 사람이 읽는 기록을 함께 고려한다.

- 내부 소통 방식이 작업 품질과 효율에 어떤 영향을 주는지 살펴본다.
- 위키, 히스토리, 포스트모텀처럼 구조화되고 읽기 쉽게 정리된 기록을 남기는 방안을 검토한다.
- 기록의 정확성, 이해 가능성, 후속 활용과 기록 생성 비용까지 효율의 범위에 포함할지 구체화한다.

## 3차: 작업 유형별로 적합한 소통 방식 탐색

종류가 다른 여러 작업으로 실험을 확장한다. 각 작업에서 어떤 소통 방식이 효율적인지, 그 차이가 어떤 조건에서 나타나는지 살펴본다.

하나의 방식이 모든 작업에 가장 적합하다고 가정하지 않으며, 1차에서 불리했던 방식도 다른 작업에서 다시 평가할 수 있다.

## 후속 확인·확장 사항

- 실제 모델 응답을 이용한 여섯 단계의 전송·해석 검증
- 고정 일정 문제의 실제 협업 난이도 확인
- 통상적인 Agent 소통을 대표할 기준 구성
- 고정 의미 특성 벡터와 공동 기호 언어를 넘어선 후속 구현
- 로컬 계산 비용의 금액 환산과 결과 해석

1차 실험의 핵심 지표는 다음 다섯 가지로 정한다.

1. 과제 성공률·결과 품질
2. 성공 1건당 총비용
3. 전체 완료 시간
4. 실제 통신량
5. 통신 처리 비용

성공 여부와 결과 품질을 먼저 평가하고, 비슷한 품질을 얻는 데 드는 비용과 시간을 비교한다. 성공 1건당 총비용에는 실패한 실행의 비용도 반영한다. 통신 처리 비용은 총비용에 포함된 내역을 별도로 분석하며 중복 합산하지 않는다. 메시지 수와 수정 과정은 보조 지표로 기록한다. 세부 측정 정의는 1차 실험 명세에서 구체화한다.
