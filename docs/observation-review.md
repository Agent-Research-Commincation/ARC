# 사후 소통 관찰과 검수 기준

상태: 구현한 사후 검수 기준. 오프라인 고정 응답으로 검증했으며 실제 모델 실행·검수 자료는 없다. [현재 상태](current-state.md), [리팩터링 작업 E](refactoring-plan-v3.md)를 참조한다.

## 평가 대상

| 대상 | 확인할 것 |
|---|---|
| 최종 결과 | 양쪽 제출·일치·유효성·선호 점수·최적해 차이 |
| 소통 과정 | 정보 공유·질문·제안·수락·수정·교정·중단의 실제 기록 |
| 전달 내용 | 명시된 개인 사실·팀 요약·후보 점수·충돌 근거의 정확성 |
| 전달 보존 | 송신 의미·전송 본문·복원 의미·수신 텍스트의 연결 |

명시된 주장만 평가한다. 상대가 실제로 믿었는지, 속으로 검증했는지는 추측하지 않는다. 수락 문장이 독립적인 검증의 증거는 아니다.

## 공통 판정 규칙

- 같은 의미는 형식에 관계없이 같은 기준으로 판정한다. 공통 의미 밖의 자유 표현은 별도 범위로 남긴다.
- 생략을 틀린 주장으로 세지 않는다. 원자료 전체를 보내지 않았다는 이유로 요약 전략을 감점하지 않는다.
- 판정 가능한 맞음·틀림과 모호함·판정 불가를 구분한다.
- 주장 종류별 분모와 검수 범위를 공개한다. 반복 횟수·고유 주장 수·모순·번복을 함께 기록한다.
- 거절된 문법에서 해석할 수 없는 의미를 억지로 추출하지 않는다. 작성 오류와 전달된 내용의 정확도는 별개다.
- 제출이 없으면 제출 영향은 null/해당 없음이다. 미검수는 미측정이며 오류 0건이 아니다.
- 오류 하나를 입력에 적용해 보는 계산은 제한된 사후 영향 분석이다. 실제 대화·비용·이해에 영향이 없었다는 증거로 확대하지 않는다.

## 검수 절차

1. 종료된 원본과 코드·문제·의미 명세 버전을 고정한다.
2. 자연어는 원문 근거를 인용해 주장·질문·행동을 추출한다. 구조화 표현은 공통 의미 명세로 추출한다.
3. 추출한 내용에 동일한 평가기를 적용한다. 자연어 전체 검수와 표본 재검수 절차를 제공한다.
4. 검수자·시각·원본 해시·검수 입력 해시·평가 코드 해시를 기록한다. 같은 작성자의 재확인을 독립 연구자 검토라고 표현하지 않는다.
5. 새 `review-id`로 결과를 저장한다. 원본 이벤트·회차 결과와 이전 검수 결과를 덮어쓰지 않는다.
6. 읽기용 기록에는 사용한 검수 버전과 미완료 항목을 표시한다. 내보내기에서 재채점하지 않는다.

검수는 실험이 끝난 후 수행하고 Agent에게 결과를 알려주지 않는다. `review`는 모델 호출 없이 별도 검수 버전을 생성한다. 자연어 입력 양식은 검수 폴더에 생기며, 이를 새 작업 파일로 복사해 작성한 뒤 `--manual-inputs`로 지정한다. 봉인된 원본·이전 검수 폴더의 파일을 직접 수정하지 않는다. 명령 예시는 [운영 안내](experiment-operation.md)를 따른다.

## 보고 가능 범위

최종 결과·사용량·전송량과 내용 검수 완료 여부를 따로 표시한다. 내용 검수가 남았더라도 확인된 실행 수치를 열람할 수 있다. 정확도 순위나 원인 설명에는 그 주장에 필요한 검수와 비교 근거가 있어야 한다. 어떤 방식이 이기는지는 검수 완료 조건이 아니다.
