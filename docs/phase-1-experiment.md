# 1차 실험 명세 · v3

상태: 구현에 적용한 실험 명세. [현재 상태](current-state.md)와 [검증 기록](v3-validation.md)을 확인한다. 이 명세의 실제 모델 실험 결과는 아직 없다.

## 연구 질문

같은 일정 과제·초기 정보·공통 행동 규칙에서 두 Agent가 여섯 소통 방식을 사용할 때, 정보 공유·질문·수정·결과·사용량이 어떻게 나타나는지 관찰한다. 표현·전송·전략·합의 절차를 포함한 구현 전체의 비교다.

## 공통 조건

- 모델: 두 Agent 모두 `gpt-5.6-luna`, 추론 수준 `high`.
- 문제: 참석자 6명·회의 3개·슬롯 12개에서 선호가 상충해 조정이 필요한 협력 일정 문제 하나. 각 Agent는 자기 팀의 가용성·선호를 받으며 공통 회의 제약을 공유한다.
- 목표: 필수 제약을 지키고 전체 참석자 선호 점수 합계를 최대화한다.
- 확인용 문제는 모델 결과를 보기 전에 고정했다. 이전 입력은 `tests/fixtures/problem.json`, 새 입력은 `config/problem.json`이다. 새 정답은 별도 검산했으며 과거 점수를 재사용하지 않았다.
- 반복: 같은 문제에서 방식별 5회. 각 회차의 A·B 세션은 새로 만들고 이전 대화·결과·정답을 제공하지 않는다.
- 자율성: 원자료·요약·질문·제안·수정의 선택과 횟수는 Agent에게 맡긴다.
- 자원: 연구용 토큰·시간·메시지·행동·합의 횟수 예산을 두지 않는다. 사용량은 관찰자가 측정한다.
- 도구·정보 격리: 자기 입력과 지정된 상대 메시지만 사용한다. 실행 중 평가기·정답·기획 대화를 제공하지 않는다.

## 여섯 방식의 범위

| 번호 | 방식 | 모델 작성·상대 수신의 범위 |
|---|---|---|
| 1 | 자연어 | 문장 원문을 그대로 전달 |
| 2 | JSON | 공통 의미 필드의 JSON 원문 전달 |
| 3 | 논리식·관계 표현 | 제한된 predicate 원문 전달. 범용 증명기 아님 |
| 4 | 고정 의미 특성 벡터 | 의미 frame을 고정 벡터와 손실 없는 정수 참조 영역으로 전송하고 복원된 frame을 수신. 학습 임베딩 아님 |
| 5 | 바이트코드 | 제한된 명령을 바이너리로 전송하고 복원된 frame을 수신. 운영체제 코드 실행 없음 |
| 6 | 공동 기호 언어 | 고정 문법의 기호 이름을 매회 합의하고 그 기호식으로 전달 |

모든 방식은 사실·팀 요약·구체적인 질문·후보 평가·재확인·제안·수정·수락·반려를 지원한다. 자연어의 자유 표현 전체와 동일한 표현력을 보장한다고 주장하지 않는다. 실제 문법과 7,790개 특성·8,192차원 벡터·정수 참조 영역은 [전송 명세](communication-contract-v3.md)에 기록한다.

## 완료와 중단

- 양쪽이 동일한 유효 일정을 제출하면 과제 성공이다. 최적해 도달 여부와 점수 차이는 별도 품질 지표다.
- 최종 제출의 불일치·제약 위반은 해당 과제 종료 사유로 기록한다.
- 명시적 진행 포기, 사용자 취소, 인프라·서비스 제한에 의한 중단은 사유를 구분한다. 과제가 해결 불가능하다는 증거로 해석하지 않는다.
- `send`는 제출을 보존하며, 전달에 성공한 `revise`만 제출을 무효화한다. 의무적인 제안·수락 메시지 수는 없다.
- 느린 응답·대화 반복을 횟수나 경과 시간만으로 실패 처리하지 않는다. 실제 서비스의 기술 한계는 별도로 기록한다.

## 다섯 핵심 지표

| 지표 | 측정 기준 |
|---|---|
| 과제 성공률·결과 품질 | 계획·시작·종료·성공·중단 수, 양쪽 제출 일치·유효 여부, 점수·최적해 차이 |
| 성공 1건당 총비용 | 실패·중단·합의·교정을 포함한 전체 측정 비용을 성공 수로 나눔. 필요한 측정이 없거나 성공이 없으면 계산 불가 |
| 전체 완료 시간 | 회차 실행·묶음 대기·초기화·종료 정리의 경계를 구분. 성공 완료 시간과 전체 시도 종료 시간을 함께 보고 |
| 실제 통신량 | 로컬 채널 본문·헤더·합계, 메시지 수, 송신·수신 텍스트 크기. API·TLS/IP 전체 트래픽과 구분 |
| 통신 처리 비용 | 인코딩·디코딩·프레이밍 시간 및 근거가 있는 금액 환산. 모델 호출에서 문제 풀이와 통신 비용은 임의 분리하지 않음 |

모델 사용량·API 단가 기반 비용 추정은 총비용과 별도로 표시한다. 실제 구독 청구액으로 표현하지 않는다. 미측정은 null이며 0이 아니다. 필요한 비용이 일부만 확인되면 부분 합계와 전체 비용을 구분한다.

품질을 먼저 보고 비슷한 품질의 비용·시간을 비교한다. 모든 지표를 임의로 한 점수로 합치거나 단일 우승 방식을 자동 선정하지 않는다. 내용 정확도는 사후 검수 범위·분모와 함께 보고한다.

## 실행 배정과 기록

회차별 선발화 `A, B, A, B, A`를 모든 방식에 동일하게 적용한다. 6단계 사전 제안자도 이에 맞춘다. 다섯 회이므로 완전한 균형이 아니며, 정보 소유 역할까지 균형화했다고 설명하지 않는다.

다중 단계 요청은 같은 커밋의 새 worktree와 고정 실행 계획을 사용한다. 시간 비교용 기본 프로필은 한 회차씩 실행하며 명시적 병렬 요청은 동시 실행 수를 기록한다. 개별 요청의 서로 다른 실행 시각과 동일 블록 측정을 구분한다.

새 결과는 원본·검수 버전·읽기용 사본을 구분해 보존한다. 사용자의 명시적 삭제 요청은 따른다. 실패를 성공으로 채우거나 아직 실행하지 않은 회차를 실험 결과로 세지 않는다.

비용의 회차 경계는 A·B 전체 모델 호출과 해당 회차의 로컬 실행 CPU다. worktree 준비·조정기 대기·중앙 복사 시간은 계획 상태 파일에 별도 기록한다. 이 경계 밖의 운영 비용까지 측정한 총청구액이라고 표현하지 않는다.
