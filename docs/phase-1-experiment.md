# 실험 조건

같은 일정 문제에서 여섯 소통 방식을 **각각 30회, 총 180회** 관찰한다. 현재 본실험은 미실행이다.

[문서 안내](README.md) · [가설과 소통 과정](experiment-plan.md) · [실행 방법](experiment-operation.md)

## 공통 문제

참석자 6명·회의 3개·시간대 12개의 일정 협업이다. Agent A는 A1·A2·A3, Agent B는 B1·B2·B3의 참석 가능 시간과 선호만 받는다. 각 회의는 한 시간대에 끝나고, 모두 참석할 수 있어야 하며, 참석자가 겹치는 회의는 동시에 열 수 없다. M1은 M3보다 먼저 열려야 한다.

가능한 일정 중 회의별 참석자 선호의 총합을 최대화한다. 같은 사람이 여러 회의에 참석하면 각 회의의 선호를 더한다. [문제 파일](../config/problem.json)을 모든 방식에 동일하게 제공하며, [검산 기준](../config/problem-reference.json)은 모델 결과가 아닌 문제 자체의 오프라인 검산 자료다. 실행기는 문제 해시가 달라지면 중단한다.

## 방식과 공통 조건

| 단계 | 소통 방식 |
|---|---|
| 1 | 자연어 원문 |
| 2 | 정해진 JSON |
| 3 | 제한된 논리식·관계 표현 |
| 4 | 고정 의미 특성 벡터로 전송하고 JSON으로 복원 |
| 5 | 제한된 바이트코드로 전송하고 JSON으로 복원 |
| 6 | 고정 문법 위에서 기호 사전 합의 |

| 항목 | 적용 조건 |
|---|---|
| 모델 | `gpt-5.6-luna`, 추론 수준 `high`, 서비스 등급 `default` |
| 반복 | 방식별 30회, 전체 180회 |
| 세션 | 매회 새 A·B 세션, 방식별 60개·전체 360개 |
| 선발화 | A·B 교대로 각 15회; 모든 방식에 같은 회차별 역할 배정 |
| 초기 정보 | 같은 문제·공통 행동 규칙과 역할별 비공개 정보 |
| 자율 선택 | 원자료·요약·질문·제안·수정 전략 |
| 연구용 실행 상한 | 토큰·시간·메시지·행동·사전 합의 횟수 예산 없음 |
| 코드와 설정 | 실행 계획 생성 시 고정; 실행 중 변경 금지 |
| 병렬 실행 | 요청된 방식별 새 worktree 사용, 같은 회차 묶음의 처리가 끝나면 다음 회차로 이동 |

설정의 출처는 [experiment.json](../config/experiment.json)이다. 실행 순서는 고정 시드로 배정하고 계획 파일에 저장한다. 단계 안에서 회차끼리 겹치지 않는다. 선발화 배정과 회차별 단계 순서는 모든 요청에서 재현 가능하게 유지한다.

새 세션에는 이전 회차의 대화가 넘어가지 않는다. worktree는 소스와 출력 공간을 분리하지만 같은 머신·계정·서비스의 캐시와 부하까지 격리하지는 않는다. 병렬 동시 수, 실행 시각, 캐시 사용량을 결과와 함께 확인한다.

## 전달과 종료 규칙

`send`는 현재 제출을 유지한다. 전달에 성공한 `revise`는 양쪽 제출을 무효화하고 다시 제출하도록 알린다. 문법에 맞지 않아 거절된 메시지는 상대에게 전달되지 않으며 거절에 든 시간과 사용량도 기록한다.

양쪽 제출의 일치와 유효성을 확인한다. Agent의 진행 포기·과제 실패, 사용자 취소, 서비스·인프라 중단, 실행 여부 미확정을 구분한다. 인프라 문제로 계획이 멈추면 아직 시작하지 않은 회차만 명시적으로 재개한다. 실패를 제외하거나 미확정 회차를 임의 재실행하지 않는다.

원본·중앙 사본은 해시로 대조한다. 정답·기획 대화·사후 검수 결과는 실험 Agent에게 전달하지 않는다. 평가는 종료 후 별도 폴더에 저장한다.

## 연구 범위

1차는 여섯 구현의 실제 행동과 결과를 관찰한다. 사람의 기록 이해도, 다른 문제에서의 적용, 표현·전송·전략·사전 합의의 요소별 분리는 [README의 2~4차 연구](../README.md)에 있다. 30회 반복만으로 인과 효과나 일반적인 추천 순위가 확정된다고 해석하지 않는다.
