# 공통 의미와 전송 명세 · v3

현재 구현은 `schedule-semantics-v3` / `schedule-codecs-v3`다. 아래 예제는 문법 설명이며 실험 문제의 사실·정답이 아니다.

## 공통 행동

작업 상태는 `send`, `revise`, `wait`, `submit`, `stop`을 허용한다. 6단계 사전 합의 상태는 `define_language`, `accept_language`, `stop`만 허용한다. 같은 상태의 스키마와 실행 검증기가 같은 행동을 허용한다.

제어 외피는 `action`, `payload`, `schedule`, `language`다. 일반 메시지는 `payload`만, 최종 제출은 `schedule`만, 사전 제안은 `language`만 사용한다. `stop`의 선택적 사유는 `payload`에 쓰며 관찰자에게만 남긴다. 상대에게 전달하지 않는다.

## 메시지 의미

| 의미 | frame 필드와 예 |
|---|---|
| 메시지 종류 | `kind`: `inform/request/propose/accept/reject` |
| 개인 사실 | `facts`: `["available","A1",0,1]`, `["preference","A1",0,2]` |
| 일정 제안 | `schedule`: `{"M1":0,"M2":1,"M3":2}` |
| 한 사람의 원자료 요청 | `requests`: `["A1"]` |
| 팀·회의·슬롯 요약 | `summaries`: `["preference","A","M1",0,3]` |
| 충돌 근거 | `reasons`: `["unavailable","M1","A1",0]`, `["overlap","M1","M2",0]` |
| 특정 사실 질문 | `questions`: `["fact","available","A1",0]` |
| 특정 요약 질문 | `questions`: `["summary","preference","A","M1",0]` |
| 후보 질문 | `questions`: `["valid",0,1,2]`, `["score",0,1,2]` |
| 후보 평가 주장 | `evaluations`: `["valid",0,1,2,1]`, `["score",0,1,2,9]` |
| 메시지 재확인 요청 | `references`: `[1,2]`. 이미 관측한 메시지 번호만 참조 |

`kind/facts/schedule/requests`는 필수이며 나머지는 생략할 수 있다. 각 목록은 비어 있어도 된다. 후보의 세 슬롯은 M1·M2·M3 순서다. 가용성·유효성은 0/1, 개인 선호는 0~3, 팀 선호 합계는 0~9, 후보 총점은 0~54다. 문법상 유효한 거짓 주장도 그대로 전송한다. 질문과 평가 주장에 정답을 제공하는 코덱 경로는 없다.

한 메시지의 같은 의미 키 중복은 거절한다. 서로 다른 메시지에 반복·모순·번복한 주장은 사후 평가에서 보존한다. 일정·참석자·슬롯으로 결정되는 유한한 의미 영역을 제한하는 문법과, 자원 사용량으로 실행을 끊는 연구용 예산은 구분한다.

## 여섯 경로

| 방식 | 모델 작성 | 실제 본문 | 상대 수신 |
|---|---|---|---|
| 1 자연어 | 문장 | UTF-8 원문 | 같은 원문 |
| 2 JSON | frame JSON | JSON 원문 | 같은 JSON |
| 3 논리식 | 제한된 predicate | predicate 원문 | 같은 predicate |
| 4 고정 벡터 | frame JSON | ACV3 헤더 + 고정 float32 좌표 + 정수 참조 영역 | 복원된 frame JSON |
| 5 바이트코드 | 제한된 어셈블리 | ACB3 이진 명령 | 복원된 frame JSON |
| 6 공동 기호 언어 | 합의한 기호의 predicate | 기호식 원문 | 같은 기호식 |

3단계는 `askfact(available,A1,0).`, `asksummary(preference,A,M1,0).`, `askvalid(0,1,2).`, `askscore(0,1,2).`, `valid(0,1,2,1).`, `score(0,1,2,9).`, `recheck(1).`을 지원한다. 5단계 대응 명령은 `QFACT`, `QSUMMARY`, `QVALID`, `QSCORE`, `VALID`, `SCORE`, `RECHECK`다. 6단계는 같은 의미들의 predicate 이름을 합의한 기호로 바꾼다. 전체 문법 안내는 실행기의 `instructions()`에서 생성한다.

## 벡터의 범위와 비용

유한한 의미 특성은 7,790개이며 패딩을 포함해 8,192개의 float32 좌표를 사용한다. 모든 사실·요약·충돌 사유·구체적 질문·후보 평가의 조합을 담는다. 값은 작은 정수 좌표로 정확히 표현하며 학습·임베딩·잠재 상태 교환은 없다.

메시지 번호는 실행 횟수에 따라 커질 수 있다. 이를 float32에 넣지 않고 가변 길이 정수로 정확히 저장한다. 본문에는 참조 개수와 각 번호의 바이트까지 포함한다. 참조가 없을 때 본문은 32,773 B이며, 공통 패킷 헤더는 여기에 별도로 더한다. 따라서 이 구현을 항상 고정 크기의 순수 벡터 전송이라고 소개하지 않는다. 압축 이득을 전제로 크기나 성공 여부를 조정하지 않는다.

전송량은 본문·공통 헤더·합계를 나누고, 작업 코덱의 인코딩·디코딩 시간과 공통 프레이밍 시간을 별도 기록한다. 사전 합의와 교정 처리도 전체 사용량에 포함한다. 자연어의 자유 표현 전체를 구조화 표현과 같은 표현력이라고 주장하지 않으며 자연어 의미·참조의 검수는 실행 후에 수행한다.
