# 공정성 검토 기준

이 문서는 새 실험을 검토할 기준이다. 삭제된 과거 실행의 수치나 원자료를 검증 근거로 포함하지 않는다. 현재 구현 상태는 [상태 문서](current-state.md), 실험 조건은 [명세](phase-1-experiment.md)를 따른다.

## 같게 할 조건과 관찰할 차이

| 구분 | 내용 |
|---|---|
| 공통으로 제공 | 같은 문제·대응되는 초기 정보·모델·공통 행동 효과·교정 정책·의미별 채점 기준 |
| 공통 기능으로 검증 | 사실·요약·구체적 질문·후보 평가·재확인·제안·수정·수락·반려 |
| 방식의 차이로 관찰 | 문법·전송 형식·메시지 길이·합의·교정 비용·Agent의 전략 선택 |
| 별도로 기록 | 역할·선발화·실행 순서·대기·공유 부하·캐시·서비스 제약 |

같은 자원 예산을 부여하는 것을 공정성의 조건으로 삼지 않는다. 사용량은 결과로 측정한다. 문법 안내의 글자 수나 실제 메시지 수가 다르다는 사실만으로 불공정하다고 판정하지 않는다.

## 문제를 판단하는 방법

실제 구현 결함, 미완료 평가, 작은 표본의 불확실성, 적용 범위, 원인 가설을 구분한다. 같은 문제를 모든 방식에 주는 것은 대응 비교의 장치이며, 한 문제의 결과가 다른 작업을 대표한다는 뜻은 아니다.

각 지적에는 관측 근거, 반대 근거, 가능한 다른 설명, 영향 범위, 해결을 확인할 검증을 붙인다. 구현 차이가 있다는 사실과 그 차이가 결과를 바꿨다는 주장은 별도다. 의심을 이유로 확인되지 않은 결함을 확정하지 않는다.

## 확인할 증거

- 같은 행동의 제출 보존·무효화·거절·중단 결과가 전 방식에서 일치하는가.
- 같은 의미의 올바른/잘못된 메시지가 동일하게 복원·평가되는가.
- 기존 연구용 상한을 넘겨도 정상적인 행동이 처리되는가.
- 자연어와 구조화 표현의 검수 범위·분모를 구분하고 미측정을 숨기지 않는가.
- 원본·평가 버전·실행 계획을 보존하고, 요청된 다섯 회를 결과에 따라 바꾸지 않는가.
- 어떤 코드·문제·환경에 적용되는 주장인지 명시하는가.

오프라인 고정 응답 검사는 기능을 검증한다. 실제 모델이 쉽게 작성·이해하는지까지 증명하지 않는다. 내부 추론을 추측해 채점하거나 같은 구현을 두 번 실행한 것을 독립 검산이라고 부르지 않는다.

## 인사이트의 범위

조건이 명확한 관측과 원인 후보는 사용자에게 유용할 수 있다. 전송 본문 감소를 곧바로 모델 비용 절감이라고 해석하거나, 비용 일부를 빼는 계산으로 해당 절차를 제거했을 때의 성과를 예측하지 않는다.

두 Agent의 추가 이득을 주장하려면 그 질문에 맞는 기준 조건이 필요하다. 코덱 단독 효과를 주장하려면 동일한 메시지로 비교해야 한다. 다양한 작업의 선택 기준을 주장하려면 문제군을 넓혀 확인해야 한다. 이런 후속 비교를 현재 관찰에 자동 추가하지 않는다.
