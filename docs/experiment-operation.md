# 실행 방법

Python 3.9 이상과 로그인된 Codex CLI가 필요하다. 프로젝트 루트에서 명령을 실행한다. 본실험은 `gpt-5.6-luna` / `high`, **방식별 30회**이며 현재 미실행이다.

[문서 안내](README.md) · [실험 조건](phase-1-experiment.md) · [지표와 검수 기준](metrics.md)

## 준비 상태 확인

```sh
python3 lab.py status
python3 lab.py check
```

두 명령은 모델을 호출하지 않는다. `check`는 오프라인 테스트를 실행하고 현재 소스의 점검 결과를 기록한다. 실제 모델 연결 검증이나 본실험 완료를 뜻하지 않는다. 연결 점검 기록이 없다는 이유만으로 본실험 요청에 예비 실행을 자동 추가하지 않는다.

## 원하는 방식 실행

아래 명령은 실제 모델을 호출한다. 선택한 방식만 같은 문제에서 30회 실행하고, 매회 A·B 세션을 새로 만든다.

| 사용자 요청 | 방식 | 명령 |
|---|---|---|
| 1단계 해줘 | 자연어 | `python3 lab.py run 1` |
| 2단계 해줘 | JSON | `python3 lab.py run 2` |
| 3단계 해줘 | 논리식·관계 표현 | `python3 lab.py run 3` |
| 4단계 해줘 | 고정 의미 특성 벡터 | `python3 lab.py run 4` |
| 5단계 해줘 | 바이트코드 | `python3 lab.py run 5` |
| 6단계 해줘 | 공동 기호 언어 | `python3 lab.py run 6` |

먼저 말하는 역할은 A·B 교대로 각 15회다. 실행 중 코드·설정·문제를 변경하지 않고, 실패도 결과에 포함한다. 성공 30회를 채우기 위한 재실행은 하지 않는다.

## worktree에서 병렬 실행

```sh
python3 lab.py run-many 1 2 3 4 5 6 --jobs 6
```

요청한 방식별로 같은 소스 커밋의 새 `.worktree`를 만들고, **각 30회·전체 180회**를 실행한다. 회차마다 여섯 방식을 한 묶음으로 배정하며 그 묶음이 끝나면 다음 회차로 이동한다. 단계 내부의 회차는 겹치지 않는다.

1·2단계만 요청하면 각 30회·총 60회다.

```sh
python3 lab.py run-many 1 2 --jobs 2
```

`--jobs`의 기본값은 1이다. 동시 수·배정 순서·선발화는 계획에 기록한다. 실행기는 별도 Git 인덱스로 소스를 고정하며 사용자 체크아웃의 HEAD와 인덱스를 바꾸지 않는다. worktree 원본과 중앙 결과 사본은 해시로 대조한다.

worker는 별도 프로세스다. 담당 서브에이전트의 진행·기록 관리까지 요청받으면 같은 계획을 관리하게 하며, `run-many` 자체를 Codex 서브에이전트 생성으로 설명하지 않는다. 실험 Agent에게 추가 지시나 정답을 전달하지 않는다.

## 결과와 실제 대화 저장

실행 후 출력된 폴더의 `report.md`에서 묶음 결과를 읽는다. 실제 시작한 회차는 `trial-01`부터 `trial-30`까지 결과를 저장하며, 미실행 회차의 대화를 만들지 않는다.

```text
results/plans/<plan-id>/                 배정·진행 상태·worktree 위치
results/experiment/<run-id>/            실행 조건·원본·회차 결과·보고서
results/reviews/<run-id>/<review-id>/    별도 사후 평가와 주석
results/readable/<batch-id>/<방식>/      내보낸 읽기용 기록
```

| 파일 | 내용 |
|---|---|
| `events.jsonl` | 실제 실행·전송·거절·제출 이벤트 원본 |
| `result.json` | 해당 회차의 결과·시간·사용량 |
| `transcript.md` | 시간순 대화와 제어 행동 |
| `Agent_A.md`, `Agent_B.md` | 각 Agent의 입력과 실제 응답 |
| `observation.md` | 대화 행동과 명시 주장 검수 상태·근거 |

결과 비교는 모델을 호출하지 않으며 같은 조건끼리 묶는다.

```sh
python3 lab.py compare
```

## 사후 검수와 읽기용 내보내기

`review`는 종료된 원본을 읽어 별도 평가 버전을 만든다. 구조화 주장은 자동 평가하고, 자연어는 작성할 주석 양식을 생성한다. 이 명령 자체는 모델을 호출하지 않는다.

```sh
python3 lab.py review <실행 폴더>
python3 lab.py review <실행 폴더> --manual-inputs <회차별 입력 경로.json> --reviewer <검토자>
python3 scripts/export_histories.py --source <실행 폴더> --review <평가 폴더> --output results/readable/<새 묶음>/<방식>
```

`--manual-inputs`는 `{"trial-01":"/절대/경로/입력.json"}`처럼 회차와 작성한 주석 파일을 연결한다. 주석에는 원문 근거와 검토자 정보를 남긴다. 검수하지 않은 자연어를 정확하다고 표시하지 않는다.

내보내기는 해당 실행의 30개 계획 회차를 안내하며 원문과 선택한 평가를 복사한다. 기존 폴더를 덮어쓰거나 모델을 다시 호출하지 않는다. `--review`를 생략하면 내용 평가 대기로 표시한다. 사람이 읽는 기록이 필요하면 실행 후 각 방식에 이 명령을 적용한다.

검수를 선택해 내보낸 폴더에는 `selected-review/`에 평가 코드·주석·봉인을 함께 저장한다. 원래 실험 소스는 `source/`에 별도로 보존한다. 해당 폴더에서 아래 명령으로 선택한 판정을 재현한다. 출력은 내보내기 바깥의 새 폴더여야 한다.

```sh
python3 replay_review.py --export . --output ../new-review-replay
```

이 명령은 모델을 호출하지 않으며 자연어를 새로 독립 해석하는 작업도 아니다. 결과 묶음과 인사이트 문서는 본실험 및 검수가 완료된 뒤 실제 생성된 파일을 연결해 작성한다.

## 중단과 보조 명령

Agent의 과제 실패나 진행 포기는 해당 회차의 결과로 남긴다. 인프라 오류는 새 회차 배정을 멈추고, 사용자 취소는 진행 중 작업에도 전달한다. 중단된 계획의 아직 시작하지 않은 회차만 아래 명령으로 재개한다.

```sh
python3 lab.py resume <계획 ID 또는 plan.json>
```

이전 원본은 보존하고 새 실행 폴더에 이어지는 기록을 만든다. 실행 여부 미확정 회차를 자동 재실행하지 않는다.

아래 보조 명령은 별도 요청이 있을 때만 실행하며 본실험 30회에 합산하지 않는다.

| 명령 | 용도 |
|---|---|
| `python3 lab.py observe` | 단계 선택 전 소통 형식을 지정하지 않은 협업 5회 관찰 |
| `python3 lab.py pilot 1` | 1단계 1회 예비 실행 |
| `python3 lab.py verify-live --stage 1` | 일정 풀이와 분리한 연결·전송 검증 |

보조 명령도 실제 모델을 호출한다. 단순 설정·문서 정리나 상태 확인에는 실행하지 않는다.
