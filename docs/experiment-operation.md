# 실행 운영 안내

v3 구현과 오프라인 검증을 완료했다. 실제 연결 검증·본실험은 별도다. [현재 상태](current-state.md)를 먼저 확인한다.

## 명령

프로젝트 루트에서 실행한다.

| 명령 | 동작 | 모델 호출 |
|---|---|---|
| `python3 lab.py check` | 오프라인 회귀·계약·코덱·평가·배정 테스트, 소스 해시 검증 영수증 저장 | 없음 |
| `python3 lab.py status` | 현재 소스의 검증 근거와 실제 연결 점검 여부 표시 | 없음 |
| `python3 lab.py run 1` | 요청한 방식만 같은 문제에서 새 A·B 세션으로 5회 | 있음 |
| `python3 lab.py run-many 1 2 3 4 5 6 --jobs 6` | 같은 소스 커밋의 단계별 worktree에서 총 30회 병렬 실행 | 있음 |
| `python3 lab.py observe` | 형식을 지정하지 않은 기본 협업 5회. 여섯 방식 비교와 별도 | 있음 |
| `python3 lab.py pilot 1` | 요청한 방식 1회 예비 실행 | 있음 |
| `python3 lab.py verify-live --stage 1` | 일정 풀이와 분리한 전송·해석 검증 | 있음 |
| `python3 lab.py resume <계획 ID 또는 plan.json>` | 종료 기록을 남기고 중단한 계획의 미실행 슬롯만 재개 | 있음 |
| `python3 lab.py review <실행 폴더>` | 별도 사후 검수 버전 생성 | 없음 |
| `python3 lab.py compare` | 같은 문제·구현·설정·CLI 버전·실행 프로필의 결과 비교 | 없음 |

연결 검증 기록이 없다는 이유로 본실험 요청에 예비 모델 호출을 자동 추가하지 않는다. 실행에 사용할 소스의 오프라인 검증이 오래됐으면 먼저 `check`를 수행한다.

## 실행과 중단

1. 검증 근거를 확인하고 요청한 단계·회차·선발화·실행 순서를 고정한다.
2. 다중 단계는 별도 Git 인덱스로 실행용 커밋을 만들고 새 worktree를 준비한다. 사용자 체크아웃의 HEAD·인덱스를 바꾸지 않는다.
3. 같은 반복 번호의 단계들을 한 블록으로 배정한다. 기본 `--jobs 1`은 한 회차씩, 명시적 병렬 요청은 지정한 동시 수로 실행한다.
4. 슬롯을 원자적으로 예약한 뒤 각 회차에 새 A·B 세션을 만든다. 단계 안에서 두 회차가 겹치지 않는다.
5. 과제 실패·Agent의 `stop`은 회차 결과로 남기고 다음 예정 회차로 진행한다. 인프라 오류는 새 배정을 멈추며, 이미 실행 중인 다른 회차는 보존한다. 사용자 취소는 진행 중인 worker에도 전달한다.
6. 원본과 중앙 사본의 해시를 확인한다. 준비·대기·회차·기록·복사 시간을 분리하고 종료 원인을 보고한다.

`resume`는 미실행 슬롯만 대상으로 한다. 이전 봉인 원본은 그대로 두고 새 파생 실행 폴더에 기존 회차를 바이트 그대로 복사한 뒤 남은 슬롯을 실행한다. `supersedes`로 관계를 기록하며 비교에서는 이전 사본을 중복 집계하지 않는다. 진행 중인 조정기가 있으면 동시 재개를 거절한다. 미확정 회차를 다시 호출해 채우지 않는다.

강제 종료로 조정기 상태 자체가 실행 중으로 남으면 자동 복구하지 않는다. 살아 있는 worker·원본·슬롯 상태를 확인해야 하며, 확인되지 않은 실행을 새 성공으로 대체하지 않는다.

## 저장 구조

```text
results/plans/<plan-id>/                 고정 계획·슬롯 상태·worktree 경로·전체 경과 시간
results/experiment/<run-id>/            실행 조건·소스 사본·원본 이벤트·회차 결과·보고서·봉인
results/reviews/<run-id>/<review-id>/    검수 근거·관찰표·수동 검수 양식·검수 버전 봉인
results/readable/<batch-id>/<방식>/      사용자가 지정해 내보낸 사람이 읽는 기록
```

각 실행은 `trial-01`부터 `trial-05`를 계획한다. 실제 시작하지 않은 슬롯에는 가짜 결과 파일을 만들지 않는다. 본실험·기본 관찰·예비 실행·전송 검증은 각각 다른 분류로 저장한다. 현재 프로젝트의 결과 저장소에는 실제 실행 자료가 없다.

## 검수와 사람이 읽는 기록

첫 `review`는 구조화 주장을 자동 검증하고 자연어 검수 양식을 생성한다. 자연어 입력은 새 작업 파일로 복사해 작성한다. `--manual-inputs`에는 `{"trial-01":"/절대/경로/검수입력.json"}` 형태의 JSON 파일 경로를 준다. 완료한 항목은 검수자와 원문 근거가 필요하다. `--recheck`로 표본 재검수 근거를 별도로 남길 수 있다.

```sh
python3 lab.py review <실행 폴더> --manual-inputs <회차별 입력 경로.json> --reviewer <검수자>
python3 scripts/export_histories.py --source <실행 폴더> --review <정확한 검수 폴더> --output results/readable/<새 묶음>/<방식>
```

내보내기는 지정한 원본과 검수 버전을 사용하며 평가기를 호출하지 않는다. `--review`를 생략하면 내용 검수 대기로 표시한다. 기존 출력 폴더를 덮어쓰지 않으며 원본·선택한 검수와 해시가 맞지 않으면 거절한다.

회차별 `transcript.md`, `Agent_A.md`, `Agent_B.md`에는 실제 입력·응답·전송·적용·거절·중단이 표시된다. 내용 정확도는 선택한 검수의 `observation.md`에서 확인한다. 신규 자료는 기본적으로 보존하고 사용자의 명시적인 삭제 요청을 따른다.
