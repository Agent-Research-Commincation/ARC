# v3 구현 검증 기록

2026-09-11. **실제 모델 호출 없이 수행한 구현 검증이다. 실험 결과나 소통 방식의 성능 순위가 아니다.**

최종 확인: **109개 테스트 통과**, `check`·`status`·`compare` 정상 동작, 문서 13개의 로컬 링크 41개에 누락 없음. `status`는 여섯 방식 모두 오프라인 검증 통과·실제 연결 미검증으로 표시했다. 프로젝트의 `results/`에는 안내 파일만 있고 실험 worktree는 없다.

## 확인한 범위

| 작업 | 구현·검증 근거 |
|---|---|
| A 공통 계약·기준 | `contracts.py`, `artifacts.py`, 구현 시작 전 `refactoring-baseline.json`, 실행 설정과 분리한 테스트 fixture |
| B 응답·사용량·취소 | 빈 큐 반복 대기, 지연 RPC 응답·사용량, EOF·취소, 고정 모델·도구 격리, 내부 추론 비수집 |
| C 회차 상태 | 옛 메시지·행동·토큰·합의 상한을 넘긴 정상 종료, 전 방식의 제출·수정·중단, 오류 후 교정 |
| D 코덱 | 유한 의미 전체 조합, 320줄·16 KB 초과 입력, 2^128보다 큰 메시지 번호, 독립 예상 바이너리, 같은 거짓 주장 보존 |
| E 평가·비용 | 같은 의미의 자연어·구조화 주장 판정, 미검수·미제출·반복·번복, 비용 누락, 실패·정리 오류 포함 |
| F 배정·worktree | 5/30개 슬롯, A·B·A·B·A 선발화, 원자적 중복 방지, 병렬 장애와 미실행 슬롯 재개, 사용자 HEAD·인덱스 보존 |
| G 기록·CLI | 이전 원본·검수 봉인 유지, 선택한 검수로만 내보내기, 변조 감지, 요청한 단계만 실행하는 CLI 연결 |

전체 테스트는 `python3 lab.py check`로 실행한다. 이 명령은 현재 소스·설정·테스트·지침 해시와 테스트 수를 `.runtime/offline-check.json`에 남긴다. `status`는 현재 해시가 그 영수증과 일치하는지 확인한다. 변경 전 상한 도달 종료를 요구했던 테스트는 새 정책의 교정·정상 종료와 옛 설정 거절 검사로 바꿨다. 제출 보존·정보 격리·고정 모델·비용 누락 검사는 유지했다.

worktree 검증은 임시 Git 저장소에서 실제 Git 명령으로 수행했다. 사용자 저장소의 HEAD·인덱스를 변경하거나 실제 실험 worktree를 생성하지 않았다. 고정 응답으로 만든 임시 대화·결과는 테스트가 끝나면 정리한다.

## Codex 연결부 확인

설치된 `codex-cli 0.153.4`의 `app-server generate-json-schema --experimental` 결과에서 사용 중인 세션 시작·턴 시작·모델 확인·턴별 사용량 필드를 확인했다. [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)를 참고했다. 이 확인은 실제 로그인·모델 호출·공급자 응답 성공의 검증과 다르다.

새 실행은 기존에 지정한 `gpt-5.6-luna` / `high`를 그대로 사용한다. 현재 가격표의 수치와 확인 날짜는 실행 설정에 보존했으며, 이번 작업에서 실제 구독 청구액을 확인하거나 새 API 가격이라고 재인증하지 않았다.

## 남은 확인과 해석 경계

- 실제 모델 연결·전송 검증과 본실험은 미실시다. 오프라인 고정 응답 성공을 모델이 문법을 잘 작성하거나 이해한다는 증거로 쓰지 않는다.
- 자연어 검수 양식과 표본 재검수 절차는 구현했다. 실제 대화의 검수는 새 실행 이후 진행한다.
- 시간·통신·비용의 측정 경계를 공개한다. 전체 네트워크 트래픽, 구독 청구액, 문제 풀이와 통신만의 모델 비용을 분리 측정했다고 주장하지 않는다.
- 한 문제·다섯 회, 3:2 선발화, 자유 자연어와 제한된 문법의 차이는 남는다. 인과 효과나 일반적인 방식 우열은 후속 비교 없이 확정하지 않는다.
- 조정기까지 강제 종료돼 실행 여부가 미확정이면 원본을 확인하기 전 자동 재개하지 않는다. 완료 상태를 추정해 채우지 않는다.

현재 준비 상태의 기준은 [현재 상태](current-state.md)다. 실제 모델 실행·사후 검수가 생기면 구현 검증과 별도로 기록한다.
