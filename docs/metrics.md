# 지표와 대화 검수 기준

1차 본실험은 **방식별 30회, 총 180회 실행을 완료**했다. 결과·대화 내용·전송 보존을 구분해 평가하며, 이 문서는 지표와 해석 기준을 설명한다. 실제 집계와 검수 범위는 [실험 보고서](experiment-report.md), 근거 발화는 [회차별 대화 기록](../result/20260912T170838Z-plan-22772406666b/README.md)에서 확인한다.

## 핵심 지표

| 지표 | 확인하는 내용 |
|---|---|
| 과제 성공률·결과 품질 | 동일한 유효 일정에 합의했는지, 가장 선호하는 일정인지, 더 좋은 대안과 차이가 있는지 |
| 성공 1건당 총비용 | 실행 전체 비용을 성공 수로 나눈 값; 비용 범위가 불완전하면 미측정 |
| 전체 완료 시간 | 초기화를 포함한 회차 시작부터 성공·실패·중단 종료까지의 경과 시간 |
| 실제 통신량 | 실험 메시지 채널에 전달된 본문 바이트와 공통 헤더 바이트의 합 |
| 통신 처리 비용 | 인코딩·디코딩·전달 준비의 로컬 CPU 시간과 측정 가능한 금액 |

## 최종 결과

성공은 두 Agent가 같은 유효 일정을 제출한 경우다. 모두 참석할 수 있는지, 회의가 겹치지 않는지, 순서 제약을 지켰는지 원자료로 검산한다. 그중 전체 참석자의 선호를 가장 높인 일정은 최적 도달로 따로 센다. 유효한 일정도 최적이 아닐 수 있다.

방식별 30회의 성공·실패·진행 포기·인프라 오류·취소·미실행·미확정을 구분한다. 미실행이나 미확정 회차가 있으면 전체 계획이 완료됐다고 보고하지 않는다. 실행기 성공 비율에 운영상 중단이 포함될 수 있으므로, 과제 수행과 운영 상태를 함께 보여 준다.

완료된 계획의 성공 비율은 성공 수 ÷ 30이다. 유효한 결과는 최적 선호 합계와의 차이도 기록한다. 잘못된 일정에 임의 점수를 부여해 유효한 결과와 평균내지 않는다.

## 비용과 시간

성공당 모델 비용은 **30회 전체 모델 비용 ÷ 성공 수**다. 사전 합의·실패·거절된 요청을 포함하며, 성공이 없거나 전체 사용량이 측정되지 않으면 계산 불가로 표시한다. 중간까지 관측한 비용 합계는 전체 비용과 구분한다.

모델 비용은 [설정 파일](../config/experiment.json)에 고정한 API 단가와 실제 기록된 입력·캐시 입력·출력 토큰으로 계산한 추정이다. 설정에 단가의 확인 날짜와 출처를 기록하며 실제 ChatGPT 구독 청구액이나 최신 단가라고 표현하지 않는다. 조건을 변경하면 별도 설정으로 구분하고 실행 중에는 바꾸지 않는다.

모델 외 비용을 측정하지 않았다면 성공당 총비용은 미측정이다. 로컬 CPU 단가도 없으면 통신 처리 금액은 미측정으로 남긴다. 모델 응답에 문제 풀이와 메시지 작성이 함께 들어가면 통신만의 모델 비용을 임의로 분리하지 않는다.

회차별 시간과 평균·중앙값·최소·최대를 보고한다. 성공 회차와 실패·중단을 포함한 모든 회차를 구분한다. worktree 준비·대기·취합 시간은 개별 회차 시간과 분리해 계획 기록에서 확인한다.

## 통신량과 모델 사용량

전송량은 본문과 헤더를 각각 기록한다. Base64로 저장한 로그 크기, 모델 API 전체 네트워크 트래픽, TLS/IP 오버헤드는 실험 채널 전송량에 포함하지 않는다.

송신 원문·수신 텍스트 크기, 메시지 수, 실행기 요청/턴 수, 입력·출력·캐시 토큰을 구분한다. 실행기 요청/턴은 Agent에게 응답을 요청한 횟수이며 최종 제출과 거절된 응답도 포함한다. 제공자 내부 호출이나 HTTP 요청 수를 뜻하지 않으며 사용량 갱신 이벤트와도 다를 수 있다.

작은 바이너리를 전달해도 모델은 복원된 JSON과 누적 대화를 읽을 수 있다. 따라서 전송 바이트 감소를 모델 비용 감소로 바꾸어 설명하지 않는다. 6단계의 사전 합의도 전체 비용·시간·통신량에 포함하고 작업 대화와 구분해 표시한다.

## 대화 내용과 전달 보존

다음 세 가지를 각각 확인한다.

| 평가 대상 | 판정 기준 |
|---|---|
| 명시한 내용 | 사실·팀 요약·거절 이유·후보 평가를 원자료와 대조 |
| 전달 보존 | 송신 의미와 변환·복원 후 수신 의미가 같은지 확인 |
| 최종 결과 | 두 제출의 일치·유효성·최적성을 별도 검산 |

모델이 틀린 값을 작성했지만 코덱이 그대로 전달했다면 내용 오류이며 복원 오류는 아니다. 문법 거절은 실제 전달된 내용 오류와 따로 집계한다. 후보를 제안했다는 사실에 “유효하다” 또는 “최적이다”라는 주장을 임의로 덧붙이지 않는다.

주장 종류별로 맞음·틀림·판정 보류와 근거를 남긴다. 같은 주장이 반복되면 반복 기록하되 독립적인 실패 사건으로 해석하지 않는다. 자연어와 구조화 표현의 주장 종류·반복·전개 방식이 다르므로 단순 오류 개수로 정확도 순위를 정하지 않는다.

유효한 후보의 점수는 참석자 선호 합계로 검산한다. 불가능한 후보의 총점은 원시 선호 합계와 실행 가능한 일정의 가치 중 어떤 의미인지 확정하지 않고 판정을 보류한다. 원시 산술합의 일치 여부는 별도 기록한다. 이 정책을 적용한 평가 버전과 주석을 함께 보존한다.

잘못된 사실을 대입했을 때 유효 일정이나 최적해가 바뀌는지는 영향 가능성이다. 상대가 실제로 그 사실을 믿었는지, 그 오류가 최종 결과의 원인이었는지까지 입증하지 않는다.

## 자연어 검수

자연어 내용은 원문에 근거한 주석을 작성한 뒤 검산한다. 주석 전에는 미측정 또는 검수 대기이며 오류 0건이 아니다. 검토자가 AI인지 사람인지 기록하고, 기존 주석 재현과 독립적인 재검수를 구분한다.

- 명시된 사실·계산·후보 평가만 판정하며 각 주장에 원문 근거를 연결한다.
- 일부 정보만 공유하는 전략은 허용한다. 단순히 보내지 않은 정보를 오류로 세지 않는다.
- 전체 목록이라고 명시한 경우와 일부 예시를 구분한다. 누락과 내용 오류를 섞지 않는다.
- 목록이 완전한지 모호하면 그 해석과 근거를 따로 남기고 억지로 맞음·틀림을 부여하지 않는다.
- 상대의 이해나 검산 여부는 실제 발화·수정·제출에서 확인하며 내부 생각을 추측하지 않는다.

## 과정 비교와 해석 범위

첫 후보가 이미 올바른 경우, 잘못된 후보가 수정된 경우, 오류가 그대로 제출된 경우를 구분한다. 추가 질문 전후에 값과 후보가 실제로 바뀌었는지 원문을 따라 검수한다. 수정 비율을 제시할 때는 전체 회차인지 오류가 발생한 회차인지 분모를 밝힌다. 이 검수는 실행 중 Agent의 행동을 강제하는 규칙이 아니다.

같은 문제·모델·설정·구현·Codex 버전·실행 프로필의 결과를 비교한다. 새 세션이어도 서비스 부하와 캐시 조건을 단계별로 통제하거나 초기화하지 않았으므로 사용량·실행 시각을 함께 확인한다. 한 문제에서의 30회 관찰로 다른 과제에서의 성능, 표현 자체의 인과 효과, 단일 Agent 대비 이득을 확정하지 않는다.
