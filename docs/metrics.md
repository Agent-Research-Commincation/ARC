## 성공과 최적은 어떻게 다른가

성공하려면 두 Agent가 같은 일정을 제출하고 참석 가능성·중복·선후 조건을 모두 만족해야 한다. 유효한 일정의 점수는 회의별 참석자 선호를 더한 값이다. 같은 사람이 여러 회의에 참석하면 각 회의의 선호에 기여한다.

이번 문제의 유효 일정은 54개이고 최적 점수는 20점이다. 자연어 3회차는 유효한 18점 일정이므로 성공이지만 최적은 아니다. 논리식 4회차는 참석 불가 조건을 위반했으므로 실패이며 유효 일정의 점수를 부여하지 않는다.

평균 시간이 짧다고 더 좋은 결과는 아니다. 논리식 방식은 빠르게 끝난 실패를 포함하면 평균 117.28초, 성공한 네 회차만 보면 125.83초다. 완료 시간은 성공·품질과 함께 읽는다.

## 비용과 전송량의 범위

성공당 모델 비용은 **계획된 5회 전체 모델 비용 ÷ 성공 수**다. 실패 회차, 사전 합의, 형식 오류로 거절된 요청도 분자에 포함한다. 성공이 없으면 성공당 비용을 계산할 수 없다.

모델 비용은 실행 당시 고정한 단가와 기록된 A·B 전체 호출의 입력·캐시 입력·출력 토큰으로 계산한다. 현재 가격을 다시 조회한 값이나 실제 구독 청구액은 아니다. 모델 호출에 문제 풀이와 메시지 작성이 함께 포함되므로 통신에만 사용한 모델 비용은 분리 측정하지 않는다. 미측정은 0이 아니라 ‘미측정’ 또는 `null`이다.

채널 전송량과 모델 입력량도 다르다. 벡터·바이트코드는 전송 후 복원된 JSON을 모델에 제공하므로 바이너리 크기가 그대로 입력 토큰이 되지 않는다. 실제 패킷 크기, 복원 후 텍스트 크기, 모델 토큰을 별도로 확인한다.

통신 CPU 시간은 로컬 변환 처리에 사용한 시간이다. 모델 응답을 기다리는 경과 시간과 같지 않으며, CPU 시간을 곧바로 통신 처리 금액으로 환산하지 않는다. 여섯 방식의 평균 CPU 시간은 비교표에 밀리초 단위로 제시돼 있다.

## 실행기 요청/턴 수와 사용량 갱신

이번 기록의 **225회는 실행기가 Agent에게 응답을 요청한 턴 수**다. 제공자 내부 호출 수나 HTTP 요청 수를 측정한 값이 아니다. 기존 JSON의 `actions`와 `model_calls`도 이 턴 수를 가리키며, 새 요약에서는 `runner_turns`로 명시한다.

사용량 갱신 이벤트는 229개다. 네 턴에서 사용량이 두 번 갱신됐기 때문에 턴 수와 다르다. 갱신 이벤트 수를 내부 호출 수로 바꾸어 해석하지 않는다. 비용 계산은 추가 갱신까지 포함한 누적 토큰을 사용하며, 네 건을 빠뜨린 비용이 아니다.

## 대화 내용의 정확성

개인 사실, 팀 요약, 후보 유효성·점수, 충돌 이유처럼 원자료와 대조할 수 있는 명시적 주장을 평가한다. 전송 과정에서 내용이 보존됐는지도 별도로 확인한다. 이번 30회에서 코덱의 내용 보존 오류는 0건이었다. 이는 Agent가 작성한 내용이 모두 참이었다는 뜻은 아니다.

- 전달하지 않은 정보는 틀린 주장으로 세지 않는다. 가용 슬롯을 단순히 나열했다면 적힌 슬롯만 판정하고, ‘이 슬롯들을 제외한 전부’라고 썼다면 전체 범위의 주장으로 읽는다.
- 일정 제안 자체에 ‘유효하다’거나 ‘최적이다’라는 주장을 임의로 덧붙이지 않는다. 최종 제출의 유효성은 별도 평가한다.
- 수락했다는 사실로 상대의 모든 수치를 믿었거나 내부 검산을 했다고 추정하지 않는다.
- 반복된 주장은 반복 기록으로 남긴다. 서로 연결된 합계·총점·최적성 오류를 독립적인 실패 사건으로 취급하지 않는다.
- 형식 오류로 전달되지 않은 응답과 상대에게 실제 전달된 내용은 구분한다. 거절된 요청의 시간·사용량도 전체 측정에는 포함한다.
- 모호한 표현과 판정 보류를 맞음·틀림으로 억지 분류하지 않는다. 아직 검토하지 않은 내용도 오류 0건으로 표시하지 않는다.

자연어 15개 메시지는 AI가 원문 전체에서 주장을 추출하고 별도 AI가 재독·검산했다. 사람의 독립 검수는 실시하지 않았다. 구조화 표현은 정해진 의미에 따라 자동 평가했다. 자연어의 자유 표현, 슬롯별 전개와 반복 때문에 주장 수와 오류 수를 그대로 방식별 정확도 순위로 사용하지 않는다.

| 모호한 표현 | 1개 | 3회차의 선호 일치 표현에서 무엇이 일치하는지 확정하기 어려움 |

[1회차 메시지 1](../results/readable/20260911T092336Z-plan-cfd3ab2b1222-review-v3-1/stage-01-natural-language/trial-01/transcript.md)과 [4회차 메시지 2](../results/readable/20260911T092336Z-plan-cfd3ab2b1222-review-v3-1/stage-01-natural-language/trial-04/transcript.md)의 목록을 일부 참인 사실의 전달로 읽으면 명시 오류는 기존 6건이다. **해당 네 목록만 전체 목록 주장으로 읽는 대안에서는 10건이 된다.** 이는 네 항목에 대한 해석 민감도이며 전체 자연어를 새 기준으로 다시 주석한 수치가 아니다. 6건과 네 누락을 무조건 더해 새로운 오류 수나 정확도 비율로 쓰지 않는다.

슬롯 8은 B1이 참석할 수 없어 두 회의의 전체 일정에 사용할 수 없었다. 따라서 이 해석 차이는 기존 최종 성공·최적 횟수를 바꾸지 않는다. ‘명시 오류 6건’은 정보의 완전성이나 사람의 오해 가능성 전체를 평가한 수치가 아니다.

새 실험에서는 일부 정보와 전체 목록 주장을 구별하는 기준, 누락·모호함의 기록 방식, 불가능 후보 점수의 의미를 결과 확인 전에 고정한다. 필요한 요약만 보내는 전략은 계속 허용한다. 기존 주석을 재생하는 것과 결과를 가리고 독립적으로 의미를 주석하는 것은 다른 작업이며, 독자의 이해 가능성 평가는 2차 연구에서 다룬다.

## 후보 점수 8건을 보류한 이유

실행 당시 지침에는 **참석 불가 등의 이유로 유효하지 않은 후보 일정의 점수**가 원시 선호 합계인지, 불가능한 일정의 효용인지 정해져 있지 않았다. 따라서 그 점수 주장 8건은 사후 평가에서 맞음·틀림을 보류했다. 이 기준은 결과를 본 뒤 보완한 것이며 실행 전에 정한 기준이 아니다.

유효한 후보의 점수는 원자료의 선호 합계로 판정한다. 유효하지 않은 후보는 유효성 주장과 산술합을 따로 확인하되, 규약이 없었던 총점 주장을 오답이나 정답으로 단정하지 않는다. 보류한 8건의 산술합은 4건 일치·4건 불일치이며, 보류를 정답으로 바꾼 것은 아니다.

이 구분은 최종 성공 29회·최적 28회나 비용·시간·전송량을 바꾸지 않는다. 자세한 발화는 [자연어 메시지별 기록](../results/readable/20260911T092336Z-plan-cfd3ab2b1222-review-v3-1/natural-language-review.md)과 [보류한 8건의 기록](../results/readable/20260911T092336Z-plan-cfd3ab2b1222-review-v3-1/review-delta.json)에서 확인할 수 있다.

## 결과를 적용할 수 있는 범위

한 문제·방식별 5회이므로 한 회차가 성공 비율을 20%p 바꾼다. 새 대화 세션을 사용했지만 공유 서비스의 캐시·부하까지 격리한 실험은 아니다. 첫 호출부터 캐시가 관측된 세션은 60개 중 20개였다.

이 자료로는 해당 구현의 대화 행동과 비용·품질 차이를 설명할 수 있다. 소통 방식의 보편적인 우열, 특정 표현만의 인과 효과, 단일 Agent보다 두 Agent가 얼마나 더 나은지는 별도의 비교가 필요하다.
