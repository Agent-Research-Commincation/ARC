# Agent 소통 방식 실험실

**AI끼리 소통할 때 어떤 방법이 효율적일까?** 두 Agent가 각자 자기 팀의 일정만 알고 있는 상황에서, 여섯 소통 방식의 대화·수정·결과·비용을 비교한다.

본실험은 **방식별 30회, 총 180회**로 계획한다. 모델은 `gpt-5.6-luna` / `high`로 고정하고, 매회 새 A·B 세션을 만든다. 전체 계획에는 360개 세션이 필요하다. 현재 이 계획의 본실험은 미실행이며 결과와 인사이트는 아직 없다.

처음 읽는다면 [실험 계획](docs/experiment-plan.md)에서 **방식별 가설 → 공통 문제와 소통 과정 → 결과를 보는 기준 → 인사이트 도출 기준** 순서로 확인할 수 있다.

## 전체 실험 설계: 1~4차 연구

아래 1~4차는 연구 범위다. 실행 명령의 1~6단계는 소통 방식 번호이며, 예를 들어 `run 1`은 자연어 방식의 30회 실행을 뜻한다.

| 연구 | 핵심 질문 | 상태 |
|---|---|---|
| 1차 · 여섯 소통 방식 관찰 | 같은 문제에서 각 방식은 어떻게 대화하고 어떤 결과·비용을 보이는가? | 방식별 30회 계획 · 본실험 미실행 |
| 2차 · 사람이 읽는 기록과 활용 | 실제 대화 기록을 사람이 정확하게 이해하고 활용할 수 있는가? | 후속 계획 |
| 3차 · 다른 과제와 문제군으로 확장 | 다른 문제에서도 같은 특성이 나타나며, 어떤 조건에서 달라지는가? | 후속 계획 |
| 4차 · 요소별 분리 실험 | 표현·전송·정보 공유·사전 합의 중 어느 요소가 차이를 만드는가? | 후속 계획 |

### 1차: 여섯 소통 방식의 행동·성과·비용 관찰

참석자 6명·회의 3개·시간대 12개인 같은 일정 문제를 사용한다. Agent A와 B는 자기 팀의 참석 가능 시간과 선호만 받으며, 무엇을 공유하고 질문하거나 수정할지는 스스로 정한다.

자연어·JSON·논리식·고정 의미 특성 벡터·바이트코드·공동 기호 언어를 각각 30회 실행한다. 먼저 말하는 역할은 회차마다 A·B를 번갈아 배정해 방식별로 각 15회가 된다. 같은 회차 번호에는 모든 방식에 같은 선발화 역할을 적용한다.

과제 성공률·결과 품질, 성공 1건당 총비용, 전체 완료 시간, 실제 통신량, 통신 처리 비용을 확인한다. 측정하지 못한 금액은 미측정으로 남기고 API 단가 기반 모델 비용 추정을 별도로 보고한다. 연구용 토큰·시간·메시지·행동 횟수 예산은 두지 않는다. 30회는 반복 실행 수이며 회차 안의 대화 상한이 아니다.

원문과 최종 결과를 함께 읽어 잘못된 후보가 수정됐는지, 그대로 수락됐는지 확인한다. 반복 관찰로 행동의 빈도와 변동을 살펴보되, 표현 방식 하나의 인과 효과나 다른 과제에서의 우열로 확대하지 않는다.

### 2차: 사람이 읽는 대화·위키·히스토리의 정확성과 이해 가능성

실제 소통 기록을 사람이 읽는 대화 문서·위키·히스토리로 만들었을 때 정보와 결정 과정이 정확하게 보존되는지 확인한다. 독자가 제안·수정·최종 결정의 근거를 찾아 이해할 수 있는지 평가하고, 기록을 만드는 비용과 시간도 함께 본다.

파일 생성과 사람의 이해도 검증은 별개다. 대상 독자, 평가 과제와 판정 기준은 후속 설계에서 정한다.

### 3차: 다른 과제와 문제군에서 적용 조건 확인

일정 문제 하나를 넘어 다른 작업과 여러 문제에서 관찰이 유지되는지 확인한다. 같은 문제를 모든 방식에 제공하고, 문제별 결과와 비용·대화 행동을 함께 비교한다.

문제 종류·문제 수·반복 횟수는 후속 설계에서 정한다. 한 문제의 결과를 모든 작업에 적용하지 않는다.

### 4차: 표현·전송·정보 공유·사전 합의의 효과 분리

1차에서 함께 달라질 수 있는 요소를 하나씩 바꾸고 나머지 조건을 고정한다.

| 비교 | 바꾸는 요소 | 고정할 요소 | 확인할 내용 |
|---|---|---|---|
| 표현 방식 | 자연어·JSON·기호식 | 문제·전달 가능한 의미·전송 조건·행동 규칙 | 대화 행동·품질·모델 사용량 |
| 전송 형식 | JSON 직렬화·고정 벡터·바이트코드 | 메시지 내용·수·복원 후 모델 입력 | 전송 크기·변환 시간·복원 정확도 |
| 정보 공유 전략 | 원자료 전체·필요한 요약 | 문제·표현·전송·공통 행동 규칙 | 품질을 유지하면서 사용량·비용이 달라지는지 |
| 사전 합의 | 사전 즉시 제공·같은 사전의 제안·수락 | 문제·문법·최종 사전·표현 의미 | 합의 절차와 이후 수행의 비용·시간 |

표현 비교에서 자연어는 중간 모델로 번역하지 않고 원문으로 전달한다. 전송 비교는 같은 메시지를 변환·복원하므로 추가 모델 호출 없이 크기와 처리 시간을 측정할 수 있다. Agent가 자유롭게 다른 사전을 만드는 효과는 같은 사전의 합의 비용과 별도로 다룬다.

2~4차는 후속 계획이며 1차 실행 요청에 자동으로 포함하지 않는다.

## 시작하기

Python 3.9 이상과 로그인된 Codex CLI가 필요하다. 프로젝트 루트에서 준비 상태를 확인한다. 아래 점검은 모델을 호출하지 않는다.

```sh
python3 lab.py status
python3 lab.py check
```

실제 모델을 사용하는 본실험 명령은 다음과 같다. 실행은 사용자가 요청한 경우에만 진행한다.

```sh
python3 lab.py run 1
python3 lab.py run-many 1 2 3 4 5 6 --jobs 6
```

첫 명령은 자연어만 30회, 두 번째 명령은 여섯 방식을 같은 소스의 worktree에서 총 180회 실행한다. 실행 후 원본은 `results/experiment/`, 읽기용 대화는 별도 내보내기를 통해 `results/readable/`에 저장한다. 아직 생성되지 않은 결과 파일을 완료 자료로 안내하지 않는다.
