# Agent 소통 방식 실험실

두 Agent가 같은 일정 문제를 풀 때 여섯 소통 방식에서 나타나는 대화·수정·결과·비용을 관찰하는 프로젝트다.

2026년 9월 11일에 방식별 5회, 총 30회를 실행했다. 유효 일정에 합의한 경우는 29회, 최적 점수에 도달한 경우는 28회다. 실제 Agent 대화와 개별 결과를 함께 확인할 수 있다.

처음 읽는다면 **[여섯 소통 방식 실험 보고서](docs/experiment-insights-v3-1.md)**에서 각 방식으로 소통하는 것이 효율적인지에 대한 가설 → 공통 회의 문제와 단계별 대화 과정 → 실험 결과 → 핵심 인사이트 순서로 살펴볼 수 있다. 기술적인 실행 명령과 평가 세부 기준은 별도 문서로 연결했다.

**다른 컴퓨터에서 읽고 검산할 자료:** [공유용 ZIP](releases/agent-communication-v3-1-20260912-reader.zip) · [SHA-256](releases/agent-communication-v3-1-20260912-reader.zip.sha256) · [사용 안내](releases/README.md). ZIP에는 최신 보고서·원대화·실행 소스·선택한 사후 평가 코드와 주석·분석 코드가 들어 있다. 압축을 푼 뒤 Python만으로 주요 판정과 수치를 재현할 수 있다. 로컬 `results/`는 Git에서 제외돼 있으므로 다른 사람에게는 이 ZIP과 체크섬을 함께 전달한다.

## 전체 실험 설계: 1~4차 연구

연구는 **소통 방식 관찰 → 사람이 읽는 기록의 활용 → 다른 문제로의 확장 → 차이를 만드는 요소의 분리**로 구성한다. 아래 1~4차는 연구 범위이며, 실행 명령의 1~6단계는 소통 방식 번호다. 예를 들어 `run 1`은 1차 연구 전체가 아니라 자연어 방식의 5회 실행을 뜻한다.

| 연구 | 핵심 질문 | 상태 |
|---|---|---|
| 1차 · 여섯 소통 방식 관찰 | 같은 문제에서 각 방식은 어떻게 대화하고 어떤 결과·비용을 보이는가? | 본실험 30회와 결과 분석 완료 |
| 2차 · 사람이 읽는 기록과 활용 | 실제 Agent 대화를 사람이 정확하게 이해하고 활용할 수 있는가? | 후속 계획 |
| 3차 · 다른 과제와 문제군으로 확장 | 다른 작업에서도 같은 특성이 나타나며, 어떤 조건에서 달라지는가? | 후속 계획 |
| 4차 · 요소별 분리 실험 | 관찰된 차이는 표현·전송·정보 공유·사전 합의 중 어느 요소와 관련되는가? | 후속 계획 |

### 1차: 여섯 소통 방식의 행동·성과·비용 관찰

참석자 6명·회의 3개·시간대 12개인 같은 일정 문제에서 두 Agent가 협력한다. 각 Agent는 자기 팀의 비공개 가용성·선호만 받고, 필요한 정보를 상대에게 요청하거나 전달한다.

자연어·JSON·논리식·고정 의미 특성 벡터·바이트코드·공동 기호 언어를 각각 5회 실행한다. 모델은 `gpt-5.6-luna` / `high`로 고정하고 매회 새 A·B 세션을 사용한다. 정보 공유·요약·질문·제안·수정 전략은 Agent가 정하며, 연구용 토큰·시간·대화 횟수 예산은 두지 않는다.

과제 성공률·결과 품질, 성공 1건당 총비용, 전체 완료 시간, 실제 통신량, 통신 처리 비용을 관찰한다. 총비용처럼 측정하지 못한 값은 미측정으로 표시하고 모델 비용 추정을 별도로 제공한다. 실제 대화를 함께 읽어 오류·수락·수정이 결과와 어떻게 연결됐는지 확인한다.

현재 완료한 실험이다. 구현 전체의 차이를 관찰한 결과이므로 표현 방식 하나의 효과나 보편적인 우열까지 확정하지 않는다. [실험 조건](docs/phase-1-experiment.md)과 [결과·인사이트](docs/experiment-insights-v3-1.md)를 확인할 수 있다.

### 2차: 사람이 읽는 대화·위키·히스토리의 정확성과 이해 가능성

Agent의 실제 소통 기록을 사람이 활용하는 대화 문서·위키·히스토리로 만들었을 때, 원래의 정보와 결정 과정을 얼마나 정확하고 이해하기 쉽게 전달하는지 확인한다.

생성한 기록을 실제 원문과 대조해 사실·제안·수정·최종 결과가 보존되는지 살펴보고, 독자가 정보와 결정의 근거를 찾아 이해할 수 있는지 평가한다. 기록을 만드는 데 필요한 모델 사용량·비용·시간도 함께 본다.

현재 제공하는 읽기용 대화 파일은 이 연구의 출발 자료다. 파일을 만들었다는 사실만으로 사람이 이해하기 쉽다는 평가가 완료된 것은 아니다. 대상 독자, 평가 과제와 구체적인 판정 기준은 후속 설계에서 정한다.

### 3차: 다른 과제와 문제군에서 적용 조건 확인

1차의 일정 문제 하나를 넘어 다른 작업 유형과 여러 문제에서 소통 방식의 특성이 유지되는지 확인한다. 모든 방식에 대응되는 같은 문제를 제공하고, 문제별 공통 조건을 맞춰 비교한다.

과제 성공·품질·비용·시간과 실제 대화 행동을 함께 관찰해, 어떤 조건에서 정보 공유나 수정이 늘어나는지 살펴본다. 문제군별 결과를 구분하여 특정 문제의 결과를 모든 작업에 적용하지 않는다.

구체적인 과제 종류, 문제 수와 반복 횟수는 후속 설계에서 정한다. 이 연구를 통해 방식별 적용 조건을 넓혀 확인하는 것이 목적이다.

### 4차: 표현·전송·정보 공유·사전 합의의 효과 분리

1차에서 함께 달라졌던 요소를 하나씩 바꾸고 나머지 조건을 고정한다. 각 비교가 어떤 차이를 설명하는지 분명하게 만드는 실험이다.

| 비교 | 바꾸는 요소 | 고정할 요소 | 확인할 내용 |
|---|---|---|---|
| 표현 방식 | 자연어·JSON·기호식 | 문제·전달 가능한 의미·전송 조건·행동 규칙 | 표현에 따른 대화 행동과 품질·모델 사용량의 차이 |
| 전송 형식 | JSON 직렬화·고정 벡터·바이트코드 | 메시지 내용·수·복원 후 모델 입력 | 전송 크기·변환 시간·복원 정확도 |
| 정보 공유 전략 | 원자료 전체·필요한 요약 | 문제·표현·전송·공통 행동 규칙 | 품질을 유지하면서 호출·토큰·비용이 달라지는지 |
| 사전 합의 | 사전 즉시 제공·같은 사전의 제안·수락 | 문제·문법·최종 사전·표현 의미 | 합의 절차의 사용량·시간과 이후 과제 수행의 차이 |

표현 비교에서는 자연어를 중간 모델로 번역하지 않고 원문으로 전달한다. 전송 비교에서는 같은 메시지를 변환·복원하므로 크기·처리 시간·복원 정확도는 추가 모델 호출 없이 측정할 수 있다. 사전 합의 비교에서 Agent가 자유롭게 다른 사전을 만드는 효과는 별도 질문으로 다룬다.

2~4차는 아직 실행하지 않은 후속 계획이다. 각 연구의 구체적인 조건을 정한 뒤 별도 요청으로 실행하며, 현재 30회의 결과에 포함하지 않는다.

## 시작하기

Python 3.9 이상과 로그인된 Codex CLI가 필요하다. 프로젝트 루트에서 `python3 lab.py status`로 모델 호출 없이 준비 상태를 확인한다.

`python3 lab.py run 1`은 자연어 방식만 새 A·B 세션으로 5회 실행한다. 번호는 자연어·JSON·논리식·고정 벡터·바이트코드·공동 기호 언어 순서다. `python3 lab.py run-many 1 2 3 4 5 6 --jobs 6`은 여섯 방식을 같은 소스의 worktree에서 병렬 실행한다. 두 실행 명령은 실제 모델을 호출한다.
