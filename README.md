# Agent 소통 방식 실험실

두 Agent가 같은 일정 문제를 풀 때, 여섯 소통 방식에서 나타나는 대화·수정·결과·비용을 관찰하는 프로젝트다.

**v3 리팩터링을 구현하고 오프라인 검증을 완료했다. 실제 모델 연결 검증과 새 본실험은 아직 실행하지 않았다. 과거 실행 결과·대화·분석·실험 worktree는 삭제 상태를 유지한다.**

[현재 구현 상태와 목표의 차이](docs/current-state.md)를 먼저 확인한다. 오프라인 구현 검증과 실제 모델 실험 결과를 구분한다.

## 여섯 소통 방식

| 사용자 요청 | 방식 | 실행 명령 |
|---|---|---|
| 1단계 해줘 | 자연어 | `python3 lab.py run 1` |
| 2단계 해줘 | JSON | `python3 lab.py run 2` |
| 3단계 해줘 | 제한된 논리식·관계 표현 | `python3 lab.py run 3` |
| 4단계 해줘 | 고정 의미 특성 벡터 | `python3 lab.py run 4` |
| 5단계 해줘 | 제한된 바이트코드 | `python3 lab.py run 5` |
| 6단계 해줘 | 고정 문법 위에서 기호 사전 합의 | `python3 lab.py run 6` |

단계는 방식 번호다. 같은 문제에서 요청한 방식만 새 A·B 세션으로 5회 실행한다. 여섯 방식 모두를 요청하면 총 30회다. 모델은 `gpt-5.6-luna` / `high`로 고정한다.

## 확정한 설계 방향

- 같은 문제·초기 정보·공통 행동 규칙과 의미별 채점 기준을 제공한다.
- 정보 공유·요약·질문·제안·수정 전략은 Agent가 선택한다.
- 연구용 토큰·시간·대화 횟수 예산을 두지 않는다. 자원 사용량은 결과로 측정한다.
- 과제 완료, Agent의 명시적 중단, 사용자·서비스에 의한 중단을 구분한다.
- 성공률·품질, 성공당 총비용, 완료 시간, 실제 통신량, 통신 처리 비용을 기록한다. 미측정은 0으로 표시하지 않는다.
- 실제 모델 결과를 보기 전에 조건을 고정하고 실패·중단을 포함해 기록한다.

4단계는 학습 임베딩이나 모델 내부 상태의 교환이 아니며, 6단계는 새로운 문법의 학습이 아니다. 단계별 관측을 소통 방식 일반의 우열이나 개별 요소의 인과 효과로 확대하지 않는다.
